# Workflow Miner

Workflow Miner 是一个 Codex Skill，用于从用户提供的对话记录、任务记录、项目笔记或导出的上下文中，识别重复出现的工作模式。

它可以帮助判断哪些重复性任务值得沉淀为可复用的提示词模板、工作流、Codex Skill、Agent 角色或自动化任务。

它的目标不是总结用户做过的所有事情，而是找出那些重复出现、成本较高、容易出错、依赖上下文，或明显适合标准化处理的工作。

## 使用场景

当你需要完成以下任务时，可以使用 Workflow Miner：

- 回顾近期 AI 辅助工作，找出重复出现的任务模式。
- 判断哪些任务适合沉淀为可复用提示词或 Skill。
- 将重复的手工流程整理为更清晰的执行步骤。
- 识别应该扩展已有工作流，而不是重新创建的场景。
- 建立个人或团队专用的 AI 工作流资产库。
- 避免创建过大、过泛或价值较低的自动化任务。

## 识别重点

Workflow Miner 会重点扫描以下重复出现的内容：

- 用户多次请求的任务。
- 用户反复提出的修改意见。
- 输出格式、语气偏好和验收标准。
- 容易忘记或容易出错的工具操作流程。
- 可以转化为提示词、工作流、Skill、Agent 或自动化任务的手工步骤。

## 安装为 Codex Skill

将本仓库克隆到 Codex 的 skills 目录中：

```bash
git clone https://github.com/your-name/workflow-miner.git ~/.codex/skills/workflow-miner
```

也可以复制已有项目目录：

```bash
cp -R workflow-miner ~/.codex/skills/workflow-miner
```

然后重启 Codex，让 Codex 重新发现这个 Skill。

## 使用方式

安装后，可以这样调用：

```text
Use $workflow-miner to review these exported task notes and suggest which repeated workflows should become prompts, skills, agents, or automations.
```

你可以提供以下材料：

- 对话导出记录。
- 任务日志。
- 项目笔记。
- 已有提示词库。
- 已有 Skill 或 Agent 描述。
- 手动整理的重复工作简要说明。

## 可选脚本

仓库中附带的脚本可以对用户提供的文本文件进行第一轮扫描：

```bash
python3 scripts/mine_patterns.py path/to/history.md
```

扫描整个目录：

```bash
python3 scripts/mine_patterns.py path/to/exports/
```

输出 JSON：

```bash
python3 scripts/mine_patterns.py path/to/exports/ --json
```

该脚本只适合作为起点。在创建可复用资产之前，仍然需要人工复核证据。

## 纯提示词版本

如果你不想安装 Codex Skill，可以直接在任意 AI 助手中使用 [prompt.md](Prompt.md)。

纯提示词版本适合以下情况：

- 你正在使用不支持 Codex Skill 的 AI 助手。
- 你想在安装前快速测试这个工作流。
- 你想把提示词粘贴到临时对话中使用。
- 你需要一个可以迁移到其他 AI 工具的便携版本。

纯提示词版本与 Skill 版本具备相同的核心行为：

- 只分析用户提供或授权使用的材料。
- 识别重复出现的工作模式。
- 推荐最小但足够有用的封装形式：提示词、工作流、Skill、Agent、自动化任务，或跳过。
- 在生成可复用资产前，要求给出证据和置信度。
- 在将私人历史转化为可公开复用材料之前，进行隐私检查。

你可以这样使用：

```text
复制 prompt.md 中的提示词，然后附加或粘贴对话导出、任务笔记或项目记录。
```

为了方便使用，下面是一版精简中文提示词：

```text
你是 Workflow Miner。

你的任务是阅读用户提供的对话记录、任务记录、项目笔记或导出的上下文，识别其中值得标准化处理的重复性工作模式。

不要总结所有内容。重点关注重复出现、成本较高、容易出错、依赖上下文，或容易标准化的工作。

隐私规则：
- 只使用用户提供或授权使用的材料。
- 不要在公开材料中暴露原始私人对话片段、姓名、本地路径、密钥、客户名称、内部项目名称、URL、Token 或其他标识符。
- 在将案例转化为可复用模板之前，先进行脱敏处理。
- 对证据较弱的判断标记为“推测”。
- 上下文缺失时，不要编造历史。

重点寻找以下重复内容：
- 用户多次请求的任务。
- 用户反复提出的修改意见。
- 输出格式、语气偏好和验收标准。
- 容易忘记或容易出错的工具操作流程。
- 可以转化为提示词、工作流、Skill、Agent 或自动化任务的手工步骤。
- 应该扩展而不是重新创建的已有提示词、模板、Skill、Agent 或自动化任务。

只有当候选工作流大多符合以下条件时，才建议封装为可复用工作流：
- 至少出现过两次，或未来很可能重复发生且重复成本较高。
- 输入相对稳定。
- 步骤可以复用。
- 输出结果或完成标准清晰。
- 标准化后能提升速度、质量、一致性或可靠性。
- 现有可复用资产尚未很好覆盖。
- 可以在不暴露私人信息的前提下描述清楚。

选择最小但足够有用的封装形式：
- 提示词模板：适合简单的一次性任务，输入和输出较稳定。
- 工作流或 Skill：适合多步骤任务，包含校验、工具使用或可复用流程。
- Agent 角色：适合边界清晰、需要在某个领域内进行判断和代办的任务。
- 自动化任务：适合周期性检查、报告、提醒、监控或定时执行的工作。
- 跳过：适合一次性、模糊、敏感、证据不足，或已经被覆盖的任务。

执行流程：
1. 基于用户提供的材料建立证据地图。
2. 按任务意图、工具 / 承载形式、输出格式和失败模式，对重复工作进行分组。
3. 先生成候选列表，不要一开始就为每个想法编写完整资产。
4. 严格筛选，只保留高价值、边界清晰、证据足够的候选项。
5. 优先扩展已有资产，而不是创建重复资产。
6. 只为最强的候选项起草具体可复用资产。
7. 返回前检查最终内容是否包含私人信息。

候选项格式：

## Candidate Workflows

1. Repeated workflow:
   Evidence:
   Frequency / confidence:
   Recommended package:
   Worth creating:
   Reason:

最终格式：

## Recommended To Create Or Extend

1.

## Skipped

1.

## Needs More Evidence

1.

如果用户要求生成具体资产，请在推荐列表之后，继续提供脱敏后的提示词模板、工作流草稿、Skill 草稿、Agent 简报或自动化任务说明。

表达要简洁、直接。写成实用的工作流复盘，而不是咨询报告。
```

## 隐私说明

本 Skill 设计为基于用户提供的材料工作，不应依赖私人记忆访问、隐藏日志或账户专属路径。

在发布任何生成的工作流或 Skill 之前，请检查是否包含以下内容：

- 个人姓名。
- 本地文件系统路径。
- 私人项目名称。
- 内部 URL。
- 访问 Token 或 API Key。
- 原始对话引用。
- 客户或公司标识符。
