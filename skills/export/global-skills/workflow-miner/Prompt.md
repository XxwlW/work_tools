# Workflow Miner 提示词版

请基于我明确提供或授权访问的对话内容、任务记录、文件内容、项目上下文或导出材料，帮我识别其中值得沉淀为“可复用工作流”的重复性任务。

你的目标不是简单总结我做过什么，而是找出那些我反复做、耗时较高、容易出错、依赖上下文、或者明显适合标准化处理的工作，并判断它们是否值得封装成固定流程、提示词、工作模板、Agent 角色或自动化任务。

隐私与证据要求：

1. 只使用我明确提供或授权访问的材料。
2. 不要在可复用产物中暴露私人对话原文、姓名、本地路径、密钥、客户名、内部项目名、私有链接、token 或其他标识符。
3. 把案例改写成通用表达后再沉淀为模板。
4. 不确定的内容必须标注“推测”或“证据不足”。
5. 如果无法访问历史记录，只基于当前提供的材料分析，不要编造。

请优先基于以下证据进行判断：

1. 最近的对话记录、任务内容、文件内容、项目上下文。
2. 我反复提到的工作场景、输出格式、修改意见和偏好。
3. 已经存在的提示词、模板、工作流、Skills、Agent 或自动化内容。
4. 当前补充的材料和明确的目标。

请广泛查找那些重复出现、耗时、容易出错、上下文依赖重，或明显适合标准化处理的工作。范围包括但不限于：编码、研究、写作、规划、沟通、运营、分析和个人事务管理。

只有当某个候选工作流满足以下条件时，才建议封装：

1. 至少重复出现过 2 次，或明显未来会反复出现且重复成本较高。
2. 输入相对稳定，处理步骤可以复用。
3. 有明确输出结果，或有清晰的完成标准。
4. 封装后能明显提升效率、质量、一致性或可靠性。
5. 不是已经被现有提示词、模板、Agent 或自动化充分覆盖的内容。

请为每个候选任务选择最小且合适的封装形式：

1. 提示词模板：适合一次性调用、结构简单的任务。
2. 工作流 / Skill：适合有固定步骤、固定输入输出、需要长期复用的任务。
3. Agent 角色：适合边界清晰、可以委派给“专项助手”的任务，例如调研助手、代码审查助手、方案评审助手。
4. 自动化任务：适合定期检查、定期生成报告、定期提醒、定期监控的任务。
5. 跳过：过于一次性、模糊、敏感、证据不足，或不适合封装的任务。

生成具体内容时，请遵守以下要求：

1. 范围要小，不要做成万能模板。
2. 要贴近我的真实工作方式和表达习惯。
3. 输入、处理步骤、输出格式要清楚。
4. 能直接复制使用。
5. 不要生成空泛、重叠、过度宏大的工作流。
6. 不确定的地方请标注“推测”，不要编造。
7. 如果已有类似内容，请优先建议扩展已有内容，而不是新建。
