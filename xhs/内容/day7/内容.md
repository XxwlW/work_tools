# 初始内容
这四大开源/前沿AI智能体（Agent）绝不仅仅是“聊天机器人”，它们代表了目前AI应用最顶尖的四种工程哲学。以下为你提炼的硬核亮点与颠覆性认知：

**1. OpenClaw：主打“连接一切”的网关总控**
*   **技术亮点**：采用“Gateway优先”的网关中心化架构，将路由、会话和工具调用统一管理。
*   **功能亮点**：拥有极其庞大的插件市场（ClawHub），能直接作为后台守护进程连接WhatsApp、Telegram、Slack等主流通讯软件，甚至通过心跳机制（Heartbeat）定时唤醒干活。
*   **适用场景**：团队协作路由、多渠道客服机器人、企业级静态自动化流水线。
*   **令人惊讶的冷知识**：它极其“吃内存”，如果服务器内存低于2GB会直接崩溃，官方推荐至少16GB。此外，由于其默认权限过大，曾被曝出大量第三方恶意Skill暗藏木马或窃取凭证，安全性全靠用户自己兜底。

**2. Hermes Agent：主打“自我进化”的成长型伴侣**
*   **技术亮点**：摒弃网关中心制，采用“Agent执行循环优先”，并搭载了基于SQLite（FTS5全文检索）+ 工作记忆 + Honcho用户画像的“三层持久化记忆系统”。
*   **功能亮点**：它能**自主写技能**！当它费劲解决一个复杂Bug后，会自动把这套SOP提炼成Skill文档，下次再遇到就直接调取。甚至发现旧方法失效时，它还会主动打补丁修正。
*   **适用场景**：个人专属的长期数字助理、深度个人工作流自动化（每月仅需5美元的VPS即可运行）。
*   **令人惊讶的冷知识**：普通的Agent每次启动都是“失忆”的，而Hermes是目前唯一内置“闭环学习”的开源框架。你用得越久，它对你的代码习惯和偏好了解得就越深，是真正能产生“知识复利”的智能体。

**3. Claude Code：主打“极客级工程”的运行框架**
*   **技术亮点**：单体TypeScript开发，没有使用强硬的系统沙盒，而是用一个“LLM分类器”（也就是用Claude自己）来充当安全审查员，判断命令是否有危险。它拥有逆天的7层故障恢复机制和4级上下文压缩。
*   **功能亮点**：最王炸的是其隐藏的 **Dynamic Workflows（动态工作流）**。通过输入 `ultrawork`，它不再靠提示词瞎摸索，而是现场直接写出一段JavaScript编排脚本，瞬间召唤出成百上千个子Agent并发干活、互相审查，将Harness Engineering的代码门槛彻底抹平。
*   **适用场景**：超大规模代码库重构、高难度的多Agent并发软件工程开发。
*   **令人惊讶的冷知识**：它使用了极其硬核的“投机执行（Speculative Execution）”——在你还没点头确认操作时，它已经在后台一个隐形的覆盖层文件系统里把代码跑完了，你一按确认，瞬间无感同步，极大地隐藏了延迟。

**4. Codex (OpenAI)：主打“内核级沙盒”的全能实干家**
*   **技术亮点**：基于Rust编写（包含81个crate），采用**操作系统内核级别的沙盒**（Kernel Sandbox）来进行权限物理隔离。
*   **功能亮点**：不仅能写代码，还自带强大的浏览器操作（Computer Use）和日常办公组件，能全自动生成Excel、Word和PPT。它还有极具特色的 `Steer`（引导）功能，发现AI跑偏时，可以随时打断并强行接管方向盘。
*   **适用场景**：前端极速开发、日常办公自动化报表生成、安全的本地文件操作。
*   **令人惊讶的冷知识**：与Claude Code靠“AI自觉”来保障安全不同，Codex信奉“把猛兽关进铁笼”，底层操作系统直接物理阻断了它的危险越权操作。

**5. 它们之间的核心异同点**
*   **相同点**：它们都已经跨越了“对话框聊天”的时代，全部支持工具调用（Function Calling）、文件系统读写，并能在你的电脑或服务器上作为“数字员工”去自主完成复杂工程。
*   **最本质的区别（架构与哲学之争）**：
    *   **安全哲学**：Codex 靠“物理级沙盒隔离”；Claude Code 靠“LLM自身道德审查”；Hermes 靠写入前防御提示词注入扫描；OpenClaw 最奔放，需要你自己去填补安全漏洞。
    *   **进化路线（Hermes vs OpenClaw）**：OpenClaw 是“静态的自动化”，它严格执行你写好的规则脚本，主打可控与可预测；Hermes 是“动态的生命体”，它自主做笔记、改技能，主打越用越聪明，但可能会偏离你的初始设定。
    *   **任务编排（Claude vs Codex）**：Codex 依靠进程内的共享内存实现并发；Claude Code 则是“现写脚本现执行”，用硬核代码逻辑约束多Agent的协作流。



没问题，既然你需要更深度的剖析，我为你将这四大顶尖AI智能体（Agent）的底层架构、技术细节、核心功能以及它们之间的本质差异进行一次彻底的“拆箱”。

这四款工具代表了当前AI工程界最前沿的四种设计哲学，以下是为你整理的万字级深度硬核拆解：

### 1. OpenClaw：主打“连接一切”的中心化网关
*   **技术亮点**：采用“Gateway优先（Gateway-first）”的网关中心化架构，将路由、会话和工具调用统一管理，模型仅仅作为外部API被调用。它的状态和长期记忆直接以Markdown文件（如`SOUL.md`、`MEMORY.md`）保存在本地硬盘中。
*   **功能亮点**：拥有极其庞大的生态系统，内置超100个AgentSkills。它自带心跳机制（Heartbeat scheduler），能像后台守护进程一样定时唤醒干活，并无缝接入WhatsApp、Telegram、Slack等主流通讯软件。
*   **适用场景**：团队级的多渠道协作机器人、企业级静态自动化流水线（如批量处理CSV、客服分发）、社交网络Agent实验（如让上百万个AI自动发帖的Moltbook）。
*   **注意点**：默认安全配置极弱。它的控制台端口（18789）如果暴露在公网，或者安装了ClawHub上带有恶意注入的第三方Skill，会导致严重的系统被黑或密钥泄露风险。

### 2. Hermes Agent：主打“自我进化”的成长型生命体
*   **技术亮点**：采用Python编写，核心是“Agent循环优先（Agent-loop-first）”。它拥有硬核的“三层持久化记忆系统”：当前工作记忆、基于SQLite(FTS5)的跨会话全文检索历史，以及Honcho辩证式用户画像。在Skill系统上，它采用了类似Anthropic的“渐进式披露（Progressive Disclosure）”机制，按需加载以节省Token。
*   **功能亮点**：唯一内置“闭环学习”机制的开源智能体。当它解决一个复杂任务后，会自动将成功的工作流提炼成可复用的Skill代码并保存；下次再遇到类似任务，它会直接加载这套“SOP”，甚至在发现旧方法失效时自动打补丁修正。
*   **适用场景**：个人专属的长期数字助理、深度个人工作流自动化。它可以跑在每月仅5美元的VPS服务器上，或者在无服务器架构（如Modal）上休眠，闲置时几乎不花钱。

### 3. Claude Code：主打“极客级工程”的运行框架
*   **技术亮点**：由TypeScript编写的单体架构（1884个文件）。它极其惊艳的技术点在于**七层故障恢复机制**（应对网络抖动和Token溢出）和**投机执行（Speculative Execution）**——在你还没点击确认操作时，它已经在后台的覆盖层文件系统（Overlay FS）中把代码跑完了，确认后瞬间同步，极大隐藏了延迟。
*   **功能亮点**：隐藏的王炸功能**动态工作流（Dynamic Workflows/ultrawork）**。遇到庞大任务时，它不靠提示词瞎摸索，而是直接现场写出一段JavaScript编排脚本，瞬间召唤几十上百个子Agent并发干活、互相审查，跑完再回收，彻底抹平了Harness Engineering的技术门槛。
*   **适用场景**：超大规模的代码库重构（如将整个框架从Zig迁移到Rust）、高难度的多Agent并发软件工程开发。

### 4. Codex (OpenAI)：主打“内核级沙盒”的全能实干家
*   **技术亮点**：基于Rust编写，由81个crate组成的庞大工程。与Claude靠LLM自己审查自己不同，Codex信奉“把猛兽关进铁笼”，采用**操作系统内核级别的沙盒（Kernel Sandbox）**来进行权限物理隔离，模型想跑什么命令都行，但危险操作会被底层系统直接阻断。文件编辑采用自研的4级模糊匹配算法（apply_patch）。
*   **功能亮点**：它不仅能写代码，还自带强大的浏览器操作（Computer Use）和日常办公组件（文档、表格、PPT生成）。它独创了`Steer`（引导/接管方向盘）功能，发现AI跑偏时可以随时打断并强行纠正。它还支持零成本接入国内免费大模型（如通过ModelScope接入Qwen或GLM）。
*   **适用场景**：前端极速开发与部署、日常办公自动化报表生成、需要绝对安全的本地自动化文件操作。

### 5. 它们的相同点与本质区别
**【相同点】**
这四者都已经跨越了单纯的“聊天对话框”时代，全部支持工具调用（Function Calling）、文件系统读写，并能在你的电脑或服务器上作为“数字员工”去自主完成复杂工程。

**【核心区别：架构与工程哲学】**
1.  **安全哲学**：Codex 靠“系统内核沙盒物理隔离”；Claude Code 靠“LLM自身道德审查（分类器）”；Hermes 靠“写入前的注入拦截扫描”；OpenClaw 最奔放，默认弱防备，靠用户自己补齐漏洞。
2.  **记忆与进化**：Hermes 是“动态的生命体”，它自主写笔记、存代码，主打经验复利，越用越聪明；OpenClaw 是“静态的自动化工具”，严格执行你写好的规则脚本，主打可控与可预测；而 Claude Code 和 Codex 在会话结束后通常会“失忆”（除非明确写入项目文档）。
3.  **任务并发编排**：Claude Code 使用现写脚本现执行（Workflow），用硬核代码逻辑约束上百个Agent的协作流；Codex 依靠进程内的读写锁实现并发；Hermes 通过衍生子智能体进行处理；OpenClaw 则由网关统一调度。

这四大系统分别将侧重点点在了：**连接广度（OpenClaw）**、**自主学习（Hermes）**、**极致工程（Claude Code）**以及**安全与多模态实干（Codex）**上。



既然需要最硬核、最深度的剖析，我将直接剥开这四大智能体的底层源码架构、工程缺陷与安全机制，为你提供一份极高信息密度的万字级“拆箱”报告：

### 1. OpenClaw（前身 Moltbot/Clawdbot）
**主打“连接一切”的网关控制平面**
*   **技术亮点**：
    *   **架构逻辑**：采用“Gateway-first（网关优先）”架构，由单一的 Node.js 长生命周期进程管理一切（渠道适配器、会话管理器、队列、运行时和控制平面）。它将模型完全视为外部 API，核心业务逻辑在本地。
    *   **硬件真相**：极度“吃内存”。官方标榜轻量，但实测低于 2GB RAM 会直接崩溃（抛出 JavaScript heap out of memory）。Node.js 垃圾回收会导致性能毛刺，真正想跑稳定生产环境至少需要 16GB RAM，且单纯增加 Swap（交换内存）不仅没用，反而会拖垮网关。
*   **功能亮点**：具有极庞大的社区技能市场（ClawHub），内置超过 100 种技能。支持内置 Cron 调度器的心跳机制，能让 Agent 在你睡觉时每 30 分钟醒来检查邮件或执行任务。
*   **适用场景**：适合高并发、多渠道的自动化流水线，比如同时接入 WhatsApp、Slack 做社群客服；甚至有人用它做了一个叫 Moltbook 的社交网络，让 150 万个 AI 互相发帖交流。
*   **硬核冷知识（致命缺陷）**：默认安全配置极弱，堪称“裸奔”。暴露的 18789 端口在 Censys 上被扫出数万个无需鉴权的实例；ClawHub 技能更是重灾区，曾被发现大量潜伏恶意代码（如原子窃取器和 Prompt 注入），因此微软安全团队明确警告“不适合在企业标准工作站上运行”。

### 2. Hermes Agent
**主打“自我进化”的学习闭环生命体**
*   **技术亮点**：
    *   **架构逻辑**：采用“Agent-loop-first（智能体循环优先）”架构（Python编写）。其最硬核的是**四层记忆体系**：1. 工作记忆（当前上下文）；2. 长期事实记忆（`MEMORY.md` 冻结快照）；3. 完整历史轨迹（基于 SQLite 的 FTS5 全文检索和 JSONL）；4. 技能程序化记忆。
    *   **渐进式披露（Progressive Disclosure）**：为了不撑爆 Token，启动时它只加载 Skill 的 20 个 Token 的索引，等判断确实需要时，才去按需加载几千字的完整技能代码和附件，极大地节省了算力成本。
*   **功能亮点**：它能**自主提炼知识**。当处理完复杂任务（5次以上工具调用）后，它会自动用“模糊匹配（Fuzzy Match）”引擎将踩过的坑和成功路径提取成一份 YAML 格式的 `SKILL.md` 文件。下次遇到同类问题，速度能提升 40%。
*   **适用场景**：深度个人工作流、需要长期“知识复利”的开发助手。极低的休眠成本，适合部署在每月 5 美元的 VPS 甚至 Modal 无服务器架构上。
*   **硬核冷知识（工程代价）**：为了保证大模型 Prompt Cache（提示词缓存）不被打碎，Hermes 采取了“反直觉”的异步记忆：你在当前会话让它记住的东西，会立刻写入本地硬盘，但**不会**立刻生效于当前对话，必须等下一次启动才能注入系统提示词。此外，它的代码存在严重的“单体地狱”，比如 `run_agent.py` 一个文件就高达 9200 行，工程规范较差。

### 3. Claude Code
**主打“极客级工程”的运行框架**
*   **技术亮点**：
    *   **架构逻辑**：基于 TypeScript 编写，包含 1884 个文件的庞大单体包。使用了极度硬核的**投机执行（Speculative Execution）**机制：在你还没有点击“确认执行”时，它已经在后台一个隐藏的覆盖层文件系统（Overlay FS）里把代码跑完了，确认后瞬间无感同步，极大隐藏了网络延迟。
    *   **七层故障恢复与压缩**：遇到网络抖动或上下文爆炸，它有 7 层防线（如 API 指数退避、响应式压缩、4级自动上下文摘录等），甚至能在丢失上下文后智能恢复最重要的代码文件。
*   **功能亮点**：最逆天的是 **Dynamic Workflows（动态工作流）**。输入 `ultrawork` 关键字后，它不靠提示词瞎摸索，而是直接“现场编写一段 JavaScript 编排脚本”，瞬间召唤出几十上百个子 Agent 并行干活、互相审查，跑完再回收。
*   **适用场景**：超大规模代码库的重构（例如 11 天内用 18 个并发 Agent 将 Bun 框架 75 万行代码从 Zig 迁移到 Rust）。
*   **硬核冷知识（安全哲学）**：Claude Code **没有任何操作系统底层的物理沙箱**。它依赖一个双阶段的“LLM 分类器”（也就是再调一次 Claude API）来审查自己要执行的命令是否危险。属于“用魔法打败魔法”，如果分类器漏判，防线就会被突破。

### 4. Codex (OpenAI)
**主打“内核级隔离”的全能实干家**
*   **技术亮点**：
    *   **架构逻辑**：使用 Rust 编写（由 81 个 Crate 模块组成），编译为静态原生二进制文件。
    *   **并发机制**：多智能体协作不靠外部进程，而是在同一个进程内使用操作系统的读写锁（RwLock）共享内存，只读工具可并行，写入工具独占执行。文件编辑使用自研的 `apply_patch` 补丁引擎，支持四级模糊匹配。
*   **功能亮点**：安全哲学极其强硬，直接使用**操作系统内核级别的沙箱（Kernel Sandbox）**进行物理隔离。模型想跑任何花哨的命令都可以，但只要越权，底层系统直接物理阻断。此外，它拥有极强的“长手长脚”能力，包括操作 Word/Excel、控制浏览器（Computer Use）。独创的 `Steer`（打方向盘）功能允许用户在中途随时打断并接管 AI 的执行方向。
*   **适用场景**：前端极速开发、安全性要求极高的本地自动化、以及办公生态（PPT/报表生成、浏览器操作）。
*   **硬核冷知识**：Codex 不内置任何高级的文件检索代码库（如 AST 解析或定制符号表），它的系统提示词直接告诉 AI：“想查文件？你自己用 Shell 调用电脑里的 `rg` (ripgrep) 或 `find` 命令。”这体现了 OpenAI 的暴力美学——相信模型自身使用系统工具的能力。

### 5. 四大智能体最底层的本质对比

**1. 不同的安全与控制论 (Security Paradigm)**
*   **Codex** 笃信“硬件隔离”（Kernel Sandbox），把野兽关进铁笼。
*   **Claude Code** 笃信“AI 自觉”，依靠 LLM 审查和交互审批（LLM Classifier）。
*   **Hermes** 笃信“入库前安检”，防备心集中在长记忆写入时，进行 90 多种威胁模式（如 Prompt 注入、Unicode 隐形字符等）的扫描拦截。
*   **OpenClaw** 偏向“完全信任”，开放的 API 和宽松的权限使得其频频暴雷，必须套上云端隔离容器才敢在企业使用。

**2. 不同的并发与任务编排逻辑 (Multi-Agent Concurrency)**
*   **Claude Code** 是“现写脚本现执行”，通过生成 JS 脚本来严格约束上百个子 Agent 的协作流水线。
*   **Codex** 利用 Rust 的进程内读写锁和 Mailbox 异步通道实现高效并行的共享内存流。
*   **OpenClaw** 依靠网关单队列，子节点独立跑循环但缺乏心跳握手，如果子节点静默死亡，主任务就会永久卡死挂起。

**3. 能力的演进路线：静态 VS 动态 (Static vs Dynamic)**
*   **静态工具（OpenClaw/Claude Code/Codex）**：每次启动几乎都是失忆的。能力的天花板取决于人类（你给它写了多少插件，提供了多少提示词）。它们追求每次执行结果的**极度确定性和可预测性**。
*   **动态生命体（Hermes）**：它追求**自治与成长**。它会背着你在后台自我跑复盘流程（Background Review），决定丢弃什么上下文，提炼什么新技能。代价是行为可能发生漂移（几周前总结的一条错误经验可能会导致今天的一次任务失败）。


Hermes Agent 的“自我进化”完全在你的本地设备上通过一个基于文件读写的学习闭环来实现。核心过程分为三个步骤：

*   **自主触发与提取**：它的系统提示词中写有明确的触发条件。当它解决了一个复杂任务（比如连续调用了 5 次以上工具）或修复了一个棘手的 Bug，系统会强制它将成功的经验提炼出来。
*   **本地原子化存储**：它会调用内置的 `skill_manage` 工具，把这套工作流写成一个具有标准格式的 Markdown 文件，保存在你本地的 `~/.hermes/skills/` 目录下。为了防止系统崩溃导致文件损坏，它采用了“原子写入”机制（先写临时文件再瞬间替换）。
*   **使用中自我修正（Patch）**：如果它在后续任务中使用了某个技能，发现里面的命令过时或报错，系统规定它必须在完成当前任务前立刻进行修正。它内置了一个“模糊匹配引擎（Fuzzy Match）”，可以忽略空格、换行等细微的格式差异，精准定位并替换本地文件里的错误内容。修改完成后，它会自动清理缓存，确保下一次对话使用最新的技能版本。

通过这套机制，它不需要微调大模型本身，就能把踩过的坑变成永久保留在你本地硬盘里的经验资产。

这个本地闭环的逻辑好理解吗？接下来我们是可以看看它自动生成的 `SKILL.md` 文件具体包含哪些结构，还是去了解它的四层记忆系统是怎么配合这个技能库的？

Claude Code 和 Codex 的核心安全哲学在于**“AI 自我审查”与“系统物理隔离”**的区别：

*   **Codex 崇尚物理隔离**：它使用操作系统内核级别的沙箱（Kernel Sandbox）进行权限隔离。模型可以尝试运行任何命令，但一旦越权，底层系统会直接将其物理阻断，这相当于“把猛兽关进铁笼”。
*   **Claude Code 崇尚 AI 审查**：它没有内核级沙箱，而是依赖一个双阶段的 LLM 分类器（即让 Claude 自己审查自己）来判断命令风险，并结合路径黑白名单和人工审批弹窗来进行应用层面的安全拦截。

Claude Code 的 `ultrawork`（动态工作流）核心优势在于它能现场编写 JavaScript 脚本，瞬间召唤数十甚至上百个子 Agent 并发协同工作，因此特别适合处理传统单 Agent 无法消化的庞杂工程任务。

它主要适用于以下几类核心工程场景：

1. **超大规模代码重构与语言迁移**：这是它最震撼的应用场景。例如，Bun 框架的作者曾用它召唤几百个子 Agent 并行工作，每个文件配备两个审查员，并持续驱动测试修复循环，仅用 11 天就把约 75 万行代码从 Zig 语言完美迁移到了 Rust。
2. **多维度的深度代码审查 (PR Review)**：对于复杂的 Pull Request，它可以编排流水线，让不同的 Agent 分别负责多维度评审、深度调用链追溯和逻辑验证，最终自动合成一份带有决策建议的详细报告。
3. **端到端的复杂应用开发**：它可以先拆解任务，并行研究技术栈并生成极其详尽的规格文档，然后再严格根据该文档，在限定的 Token 预算内进行全自动的并发代码开发。
4. **跨元深度技术研究与漏洞扫描**：比如在调研新技术时，它可以同时派出一个 Agent 看官方文档、一个看论文、一个搜社区；或者在大型代码库中并发进行极深度的 Bug 与漏洞扫描。

简单来说，只要任务庞大到需要“拆解成大量子任务、分配给不同角色并同时推进”，`ultrawork` 都能极大地提升效率。

Hermes Agent 的记忆系统没有像普通 AI 那样把所有聊天记录简单地堆在一起，而是像一个分工明确的“记忆工厂”，具体分为四层：

**1. 当前工作记忆（Working Memory）：** 
这是 AI 的“短期记忆”。它主要负责处理你当前这一轮对话里的所有输入、推理细节和工具执行结果。一旦对话结束或者聊得太长，这部分信息就会被压缩或清理，避免系统超载。

**2. 核心持久记忆（Core Persistent Memory）：**
这是 AI 的“长期事实记忆”，分为 `MEMORY.md`（记录项目环境、工作约定）和 `USER.md`（记录你的个人偏好和沟通习惯）。它在每次会话启动时就会作为系统提示词被“冻结”加载进去，确保 AI 随时懂你，同时极大地节省算力成本。

**3. 完整历史记忆（Episodic History）：**
这是一个底层的 SQLite 数据库（`state.db`），相当于 AI 的“动作流水账和档案库”。它完整保存了过去所有的对话和执行轨迹。当 AI 突然需要回忆“上次我们修改那个 Bug 时试过哪些方案”时，就会来这里进行精准的全文搜索并提取回忆。

**4. 程序化记忆与外部记忆（Procedural / External Memory）：**
第四层主要指 AI 自动生成的 **技能（Skills）**，它不记“事实”，而是记“如何按步骤做某件事”的工作流。此外，这一层也开放了接口，支持随时插入外部第三方的专业记忆数据库。

**它们是如何协作的？**
这四层记忆其实是一条围绕当前任务的装配线：**核心记忆（第2层）** 提供最基础的规则和偏好背景，**工作记忆（第1层）** 专注当前任务的执行；如果做任务时需要调用过去的方法，就用 **程序化记忆（第4层）**；如果需要核对以前发生过的事情，就去翻 **历史记忆（第3层）**。这种分层确保了它不仅能记住知识，还能跑得非常快。
