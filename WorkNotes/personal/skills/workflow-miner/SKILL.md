# Workflow Miner

使用本 Skill，将零散、混乱的工作历史整理为少量高价值、可复用的工作流。目标不是总结用户做过的所有事情，而是找出那些重复出现、成本较高、容易出错，或高度依赖上下文、值得标准化处理的工作。

## 隐私保护原则

- 仅使用用户明确提供或授权使用的历史记录、导出内容、文件或上下文。
- 在生成公开内容时，不要暴露原始私人对话片段、姓名、本地路径、密钥、客户名称、内部项目名称、URL、Token 或其他标识符。
- 在将案例转化为可复用模板之前，应先进行脱敏处理。
- 对证据不足的判断标记为 `inferred`，不要在上下文缺失时编造历史。
- 优先使用通用类别，而不是具体私人细节。例如使用 `文档编辑工作流`，而不是某个具体私人文档标题。

## 识别重点

重点扫描以下重复出现的内容：

- 用户多次请求的任务。
- 用户反复提出的修改意见。
- 输出格式、语气偏好和验收标准。
- 容易出错、容易忘记或容易被破坏的工具操作流程。
- 用户希望停止重复执行的手工步骤。
- 已存在的提示词、模板、Skills、Agents 或自动化任务，优先判断能否扩展，而不是重新创建。

常见领域包括代码修改、资料调研、写作、PRD、方案文档、UI/UX 设计、项目规划、数据分析、测试评估、内容运营、沟通准备，以及其他重复性个人工作流。

## 值得封装为 Skill 的判断标准

只有当候选工作流满足以下大多数条件时，才建议创建或更新可复用工作流：

- 至少出现过两次，或未来很可能重复发生且重复成本较高。
- 输入相对稳定。
- 执行步骤可以复用。
- 输出结果或完成标准清晰。
- 标准化后能提升速度、质量、一致性或可靠性。
- 现有提示词、Skills、Agents 或自动化任务尚未很好覆盖。
- 该工作流可以在不暴露用户私人信息的前提下被描述清楚。

## 封装形式判断

选择最小但足够有用的形式：

- `提示词模板`：适合简单的一次性任务，输入和输出较稳定。
- `工作流 / Skill`：适合多步骤任务，包含校验、工具使用或可复用流程。
- `Agent 角色`：适合边界清晰、需要在某个领域内进行判断和代办的任务。
- `自动化任务`：适合周期性检查、报告、提醒、监控或定时执行的工作。
- `跳过`：适合一次性、模糊、敏感、证据不足，或已经被现有资产覆盖的任务。

## 执行流程

1. 建立证据地图。
   - 阅读用户提供的历史记录和当前材料。
   - 按任务意图、承载工具、输出格式和失败模式，对重复工作进行分组。
   - 当文件较多时，可使用 `scripts/mine_patterns.py` 进行第一轮文本扫描。

2. 先生成候选项。
   - 不要一开始就为每个想法编写完整 Skill。
   - 对每个候选项记录证据、频率 / 置信度、推荐封装形式，以及是否值得创建。

3. 严格筛选。
   - 只保留高价值、边界清晰、证据足够的候选项。
   - 优先更新已有可复用资产，而不是创建重复资产。
   - 控制范围，避免设计成万能型巨型 Skill。

4. 起草可复用资产。
   - 包含名称、使用场景、输入、步骤、输出格式、质量检查点和注意事项。
   - 使用通用且脱敏后的示例。
   - 如果生成 Codex Skill，应将触发条件写入 YAML 的 `description`，保持 `SKILL.md` 简洁，并将较长示例放入 references。

5. 校验隐私与实用性。
   - 检查草稿中是否包含私人姓名、路径、URL、Token、内部标识符或原始引用。
   - 确认工作流具备具体步骤和可观察的完成标准。
   - 对不确定的建议标记为 `needs more evidence`。

## 候选项输出格式

在创建任何资产之前，先使用以下紧凑格式：

```markdown
## Candidate Workflows

1. Repeated workflow:
   Evidence:
   Frequency / confidence:
   Recommended package:
   Worth creating:
   Reason:
```

## 最终输出格式

结尾使用以下格式：

```markdown
## Recommended To Create Or Extend

1.

## Skipped

1.

## Needs More Evidence

1.
```

如果用户要求生成具体资产，应在推荐列表之后，继续提供脱敏后的提示词、工作流、Skill 草稿、Agent 简报或自动化任务说明。

## 风格要求

表达要简洁、直接。写成实用的工作流复盘，而不是咨询报告。真正有用的答案应该回答：什么值得标准化、为什么值得标准化，以及如何在不泄露私人上下文的前提下变成可复用资产。
