**1\. 模块启动与参考线初始化**

\[03-30 10:54:57\] start APAMap\_Process...

* **解释**：APA（自动泊车辅助）地图处理模块的进程被主控（或状态机）唤醒，开始单帧的建图计算。
```

\[03-30 10:54:57\] \==RefercLineInit==PtNum\_Right(0)==Pt1(5128.37,9989.62)

\[03-30 10:54:57\] \==RefercLineInit==PtNum\_Right(0)==Pt2(13024.98,-5811.88)
```
* **解释**：初始化右侧参考线（Reference Line）。参考线在规划中通常用于对齐车道或约束泊出角度。PtNum\_Right(0) 表示当前右侧参考线点序或有效状态（0可能为初始值）。Pt1 和 Pt2 构成了初始的基准向量。

**2\. 接收全局与局部地图输入数据**
```
\[03-30 10:54:57\] \==INPUTDATA==TOTALMAP==T(1584726)==carpose: 66794.432304,-139441.506248,-1.104264, anchor: 66794.432304,-139441.506248,0.000000, ODobjnum: Square(37),Polygon:(4)(0(7,2,-2493,-321),1(7,3,-565,701),2(7,7,-1489,-2250)),OrView: 0,TopView: 172,debug(0,0,0,0,0) p1(-1845,-738),p13(794,1981)
```
* **解释**：获取时间戳 1584726 的全局地图（TOTALMAP）原始感知数据。  
  * carpose：自车在全局坐标系下的位姿 $(x, y, \\theta)$，$\\theta=-1.104$ 弧度。  
  * anchor：锚点坐标。此时锚点与自车位置重合，意味着即将以自车当前位置为原点建立局部栅格地图或规划坐标系。  
  * ODobjnum：障碍物检测（Obstacle Detection）包含 37 个矩形（常见为车位框或车辆边界）和 4 个多边形（可能是路沿、不规则障碍物）。
```
\[03-30 10:54:57\] \==INPUTDATA==TOTALMAP==T(1584726)==carpose: 0.003954,4999.999690,0.000000, anchor: 62328.764401,-141690.463554,-1.104264, ODobjnum: Square(37)...
```
* **解释**：坐标系转换确认帧。anchor 发生变化，carpose 变为了近乎 $(0, 5000, 0)$，说明算法内部进行了一次坐标系平移旋转转换（通常为了避免浮点数精度丢失，或对齐到某个虚拟规划原点）。

**3\. 泊出建图指令触发**
```
\[03-30 10:54:57\] \==First APAMapParkout Build cmd(6)===request\_cnt(1)==
```
* **解释**：接收到状态机发来的第1次完全泊出（Parkout）建图指令，命令字枚举为 6，请求计数器为 1。

**4\. 全局地图车位遍历与初筛（First Pass）**
```
\[03-30 10:54:57\] \==ParkOutSlotInfoFromTotalMap==First==SlotPt:0(11171.00,14082.00),1(13366.00,14084.00),...==CurLabel(25)

*(此处省略多行相似的 First==SlotPt log，对应周边不同车位)*
```
* **解释**：第一轮扫描（First Pass）。系统遍历输入数据中的所有可用车位框。  
  * SlotPt: 0, 1, 2, 3 为车位四个角点坐标。  
  * CurLabel(25)：感知语义标签为25，根据泊车常规定义，这代表“垂直车位”。算法此时在内存中构建周边空车位/占用车位的拓扑地图。

**5\. 核心逻辑：基于邻近车位推导自车车位**
```
\[03-30 10:54:57\] \==APAMap\_ParkingOutBuildCurCarPosSlotByTwoNearbySlot==Valid==bResult1(1)==NearBySlotNumsByAngled(0)==NearBySlotNumsByLadder(0)==NearBySlotNumsByPerpen(0)==k(2)
```
* **解释**：这是实际工程中非常经典的处理策略（参考文档中的情况3：车位框残缺）。当前自车所在的车位感知可能被自身车体遮挡导致残缺，算法调用该函数，利用左右邻近的车位框来**补全/构造**自车当前的车位。  
  * bResult1(1)：表示构造成功。  
  * k(2)：表示找到了2个符合拓扑关系的参考邻近车位。
```
\[03-30 10:54:57\] \==ParkOutSlotInfoFromTotalMap==First==SlotPt:0(-1253.00,8797.00),1(872.00,8788.00),2(838.00,3291.00),3(-1287.00,3302.00)==CurLabel(25)

* **解释**：算法把基于邻近车位构造出的自车关联车位点存入内存列表。
```
**6\. 地图车位复筛与校验（Second Pass）**
```
\[03-30 10:54:57\] \==ParkOutSlotInfoFromTotalMap==Second==SlotPt:0(11171.00,14082.00)...

\[03-30 10:54:57\] \==Test==1111=======bResult(0)==bResult1(0)==bBuildAngledByNeaybyFlag(0)==Label(25)

\[03-30 10:54:57\] \==Test==4444=======bResult(0)==bResult1(0)==DataNearByNum(1)==bCheckIfLadderSlot(0)

*(此处省略中间遍历过程的数十行验证步骤，DataNearByNum 从1一直递增到14)*
```
* **解释**：第二轮扫描（Second Pass）与规则引擎校验。算法复核构造出来的所有车位关系。  
  * Test== 1111 / 4444：代表不同阶段的硬核逻辑校验探针（例如长宽比检测、重叠度检测）。  
  * bCheckIfLadderSlot(0)：检测该车位是否为阶梯车位（False）。  
  * 此时 bResult(0) 说明前 13 个参考车位均不是自车所在的最终目标车位，仅作为地图背景。
```
\[03-30 10:54:57\] \==APAMap\_ParkingOutBuildCurCarPosSlotByTwoNearbySlot==Valid==...==k(2)

\[03-30 10:54:57\] \==Test==1111=======bResult(0)==bResult1(1)==bBuildAngledByNeaybyFlag(0)==Label(25)

\[03-30 10:54:57\] \==Test==2222=======bResult(0)==bResult1(1)==DataNearByNum(14)==Label(25)

\[03-30 10:54:57\] \==Test==3333=======bResult(1)==bResult1(1)==DataNearByNum(14)==bCheckIfLadderSlot(0)

\[03-30 10:54:57\] \==Test==5555=======bResult(1)==bResult1(1)...

\[03-30 10:54:57\] \==Test==6666=======bResult(1)==bResult1(1)...
```
* **解释**：当遍历到第 14 个数据块（即第一轮构造出的自车关联车位）时，触发全面校验。  
  * Test ==  3333/5555/6666 对应算法的纵深检测、角度合法性检测、碰撞边界检测等。  
  * 此时 bResult(1) 翻转为1，说明当前推导出的车位完全符合几何规则与泊出起点的物理条件。

**7\. 锁定自车当前车位**
```
\[03-30 10:54:57\] \==ParkOutGetLocSlotFromTotalMap==Result(1)==Cause(0)=LocSlotPts:0(-1253.00,8797.00),1(-1287.00,3302.00),2(838.00,3291.00),3(872.00,8788.00),LocLabel(25),LadderSlot(0),SlotNumNearBy(14)
```
* **解释**：车位锁定结果输出。  
  * Result(1)==Cause(0)：成功从全局地图提取出定位车位（LocSlot），无报错。  
  * LocSlotPts：输出泊出起始车位的精确四个角点坐标。这是后续所有碰撞检测（碰撞树/距离场计算）的强约束边界。

**8\. 生成规划所需的几何参数与地图边界**
```
\[03-30 10:54:57\] \==ParkOutGetSlotInfoFromLocVPLSlotByTotalMap===SlotPt:0(-1253.00,8797.00),1(-1286.99,3302.01),2(838.00,3291.00),3(872.00,8788.00),Obj2Pt(872.00,8788.00),Obj1Pt(-1253.00,8797.00),ObjAng(-0.35),OrgAng(-90.24),Dis(-94.16,317.09),CarOffsetX(5.73),MinSlotDpth(4883.61),VPLSlotDpth(5497.10)
```
* **解释**：根据锁定的自车位，计算路径规划（如混合A\*或基于几何的圆弧规划）直接依赖的工程参量：  
  * Obj1Pt 和 Obj2Pt：泊出开向的两个基准物理角点（通常为左右两侧车位开口处的顶点，用于约束泊出时车头/尾的扫掠半径）。  
  * ObjAng(-0.35)：两角点连线与坐标轴的夹角。  
  * OrgAng(-90.24)：车位朝向角度，-90度左右证明这是一个与通道垂直的车位。  
  * CarOffsetX(5.73)：自车中心轴线偏离车位中心线的距离，表明车辆略微偏向一侧（5.73mm或cm，取决于系统单位，通常偏置量极小，车辆停得较正）。  
  * VPLSlotDpth(5497.10)：视觉融合确定的车位深度约为5.5米。
