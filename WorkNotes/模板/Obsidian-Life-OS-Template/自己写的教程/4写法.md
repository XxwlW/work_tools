## 为什么有这么多写法？

因为记录不是为了固定格式，而是为了在不同场景下少写重复信息。

有时候一句话就能说完：

```md
- 和[[小明]]聊天
  - 2, 1
```

有时候一件事下面有好几个人：

```md
- 去旅游
  - [[小明]]
    - 5, -1
  - [[小刘]]
    - 5, 3
```

有时候只是想标记“这个人和这篇事件有关”，还没写具体内容：

```md
- [[小刘]]
```

这些写法看起来不同，但核心都一样：最后都要解析成一条条“最小原子”。

## 最小原子是什么？

最小原子就是可以独立进入人物、项目、钱包详情页的一条记录。

它通常需要三样东西：

1. 描述：这条记录显示成什么。
2. 链接：这条记录和谁、哪个项目、哪个钱包有关。
3. 值：时间、情绪或金额。

普通事件可以没有值，系统会把值缺省成 0。

记账不能没有金额。钱包账单必须写金额。

## 严格写法是什么？

严格写法就是每条最小原子都自己写全，不依赖父级，也不依赖缺省。

普通事件：

```md
- 和[[小明]]聊天
  - 2, 1
```

多人事件，如果每个人的值不同，就拆开写：

```md
- 和[[小明]]聊天
  - 2, -1
- 和[[小刘]]聊天
  - 2, 3
```

账单：

```md
- [[样例工资卡]] 买水果 #记账 #零食
  - -3
```

严格写法的好处是最清楚，几乎不会误解。

它的缺点是重复。比如“去旅游”这类共同背景，每个人都写一遍会很烦。

## 为什么允许省略？

为了少写重复内容。

如果父级已经写了背景，子项可以只写人和数值：

```md
- 去旅游
  - [[小明]]
    - 5, -1
  - [[小刘]]
    - 5, 3
```

这里 `[[小明]]` 和 `[[小刘]]` 自己没有描述，所以会向上拿父级“去旅游”。

但是如果子项已经写完整了，就不会再拼父级：

```md
- 去旅游
  - 和[[小明]]聊天
    - 2, 1
```

这里 `和[[小明]]聊天` 已经是完整原子，父级“去旅游”只是分组，不参与拼接。

## 缺省规则

缺省是兜底，不是优先规则。

普通事件缺值：

```md
- 和[[小明]]聊天
```

会进入小明详情页，值缺省为 0。

普通事件缺描述：

```md
- [[小刘]]
```

会进入小刘详情页，值缺省为 0，描述缺省为当前文件链接。

账单缺描述：

```md
- [[样例工资卡]] #记账
  - -20
```

会生成账单，金额是 `-20`，描述缺省为当前文件链接。

账单缺金额：

```md
- [[样例工资卡]] #记账
```

不会生成账单。记账不能缺省金额。

## 心法是什么？

心法就是三句话：

1. 先看当前行能不能自己成为最小原子。
2. 拼不出来时，再从父级或文件链接里补。
3. 已经成原子的内容，要隔离，不再继续和父级拼。

换成更短的话：

> 先自足，缺什么补什么；已经自足就隔离。

如果不知道怎么写，就先用严格写法。等熟了之后，再用父级、省略和缺省来减少重复。
