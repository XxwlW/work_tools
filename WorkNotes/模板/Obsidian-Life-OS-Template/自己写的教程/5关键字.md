## 关键字是什么？

这里说的关键字，是最小原子已经成立之后，额外补充的信息。

它不是用来拼最小原子的。

例如：

```md
- 和[[小明]]聊天
  - 2, 1
```

这条事情已经成立了。它有描述、链接和值。

如果要补充“这件事实际是哪天发生的”，再加关键字：

```md
- 和[[小明]]聊天 @2026-05-08
  - 2, 1
```

这里的 `@2026-05-08` 才是关键字。

## 事情的关键字

事情这里先只讲一个关键字：`@日期`。

### `@日期`

`@日期` 用来指定事情实际发生日期。

```md
- 和[[小明]]聊天 @2026-05-08
  - 2, 1
```

支持这些格式：

```md
@2026-05-08
@20260508
@2026/05/08
```

如果不写，系统会使用日记日期、文件日期或创建时间。

`@日期` 会被系统识别，不会当成正文描述展示。

## 账单的关键字

账单的最小原子先长这样：

```md
- [[样例工资卡]] 买水果 #记账
  - -3
```

这里 `#记账` 是账单原子的组成部分，不是本篇说的“附加关键字”。

账单关键字是账单成立后，继续补充的信息，比如入账日、服役天数、分期、来源。

## 账单关键字写在哪里？

约定：

1. 第一个子项写值。
2. 第二个子项写关键字，也就是这条账单原子的补充信息。

例如：

```md
- [[样例信用卡]] 买会员 #记账
  - -30
  - BILL:2026-05-20
```

第一子项 `-30` 是值。  
第二子项 `BILL:2026-05-20` 才是关键字。

不要把关键字和金额写在同一个子项里。
也不要把关键字继续拆到更深层级。严格写法就是：账单正文下面，第一子项是值，第二子项是补充信息。

## `BILL:`

`BILL:` 用来指定实际产生账单的日期。

```md
- [[样例信用卡]] 买会员 #记账
  - -30
  - BILL:2026-05-20
```

比如你淘宝买了一件在 5月20号买了一件衣服，把这个账单记了下来，到了5月30号才确认收货产生账单，就可以用BILL指定这笔账单实际的发生事件。
实际发生时间主要还影响后面 `#贷款` 的入账。

## `LIFE:`

`LIFE:` 表示这笔支出服务多少天。

```md
- [[样例信用卡]] 买一年会员 #记账
  - -120
  - LIFE:365
```

常见写法：

```md
LIFE:365
LIFE:365@@
LIFE:365@90
LIFE:365@2026-12-31
```

含义：

- `LIFE:365`：预计服务 365 天。
- `LIFE:365@@`：寿终正寝，实际也按 365 天。
- `LIFE:365@90`：预计 365 天，实际用了 90 天。
- `LIFE:365@2026-12-31`：指定退役日期。
@@ 用于 话费这些可预期的。 其他则是在发现实际退役后补充的。

## `MULTI:`

`MULTI:` 记录分期或还款规则。

```md
- [[样例信用卡]] 买设备 #记账
  - -3000
  - MULTI:3@3000
```

`MULTI:3@3000` 表示拆成 3 期，总还款金额按 3000 计算。

如果不写 `@3000`，总金额默认用这条账单自己的金额。

`MULTI:` 只是分期规则。它真正参与还款计算，通常要和 `#贷款` 一起用：

```md
- [[样例信用卡]] 买设备 #记账 #贷款
  - -3000
  - BILL:2026-05-20; MULTI:3@3000
```

钱包看到 `#贷款` 后，会生成还款记录。计算顺序是：

1. 先用 `BILL:` 作为入账日；没有 `BILL:` 就用日记或文件时间。
2. 再按钱包自己的账单日、出账日、还款日，算出第一期还款日。
3. 如果有 `MULTI:`，从第一期开始每月排一期。
4. 总金额平均分到每一期，除不尽的零头放在第一期。

如果有 `#贷款` 但没有 `MULTI:`，钱包会按一笔还款处理。

## 贷款相关写法

`#贷款` 是一个约定：这条账单需要进入钱包的还款计算。

最简单的贷款写法：

```md
- [[样例信用卡]] 买设备 #记账 #贷款
  - -3000
```

这会生成一笔还款记录。还款日由钱包页的还款规则计算。

指定入账日：

```md
- [[样例信用卡]] 买设备 #记账 #贷款
  - -3000
  - BILL:2026-05-20
```

`BILL:` 会影响这笔贷款算进哪一期账单。

指定分期：

```md
- [[样例信用卡]] 买设备 #记账 #贷款
  - -3000
  - BILL:2026-05-20; MULTI:3@3000
```

这里是 3 期，总还款金额 3000。每期 1000。

指定每次还款：

```md
- [[样例信用卡]] 买设备 #记账 #贷款
  - -3000
  - 2026-06-15@1000#2026-07-15@1000#2026-08-15@1000
```

这种写法直接写明每次还款的日期和金额。多个还款记录用 `#` 连接。

结构化笔记里也可以写：

```md
---
值: -3000
标签:
  - "#贷款"
关联:
  - "[[样例信用卡]]"
创建时间: 2026-05-20
还款信息: BILL:2026-05-20; MULTI:3@3000
---
```

结构化笔记的 `还款信息`，和列表里的第二个子项作用一样。

## `SOURCE:`

`SOURCE:` 记录来源链接。

```md
- [[样例工资卡]] 买水果 #记账
  - -3
  - SOURCE:[[水果订单截图]]
```

来源可以是订单、发票、截图笔记。  
`SOURCE:` 不会污染账单描述。

## 多个关键字怎么写？

写在同一个关键字子项里，用分号隔开：

```md
- [[样例信用卡]] 买一年会员 #记账
  - -120
  - BILL:2026-05-20; LIFE:365; SOURCE:[[会员订单截图]]
```

这条账单的第一子项是 `-120`，第二子项就是全部补充信息。

当前解析对旧写法有一定兼容，但教程里按严格写法来：多个关键字仍然放在第二个子项里。

## 心法

先写原子，再写关键字。

事情关键字：

```text
@日期
```

账单关键字：

```text
BILL:
LIFE:
MULTI:
SOURCE:
@
#
```

账单里记住顺序：

```md
- 账单正文 #记账
  - 值
  - 关键字
```
